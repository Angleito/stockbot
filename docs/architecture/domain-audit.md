## Current strengths

The repo already implements much of the palantir-domain model correctly; these decisions must be preserved, not "fixed":

- **Provider-agnostic `app/domain/`**: portfolio (`Position`, `PortfolioSnapshot`, `BrokeragePositionInput`), market (`Entity`, `Security`, `TickerAlias`, `SecurityResolution`, `Quote`), risk (`Mandate`, `RiskLimit`, `RiskBreach`, `RiskEvaluation`, `EvaluationIssue`) are frozen dataclasses with no storage/vendor imports; package docstrings state the intent explicitly ("provider-agnostic by design").
- **Deterministic functions, LLM interprets**: `portfolio/valuation.py`, `portfolio/snapshot.py`, `risk/evaluation.py` are pure Decimal math with structured `EvaluationIssue` codes instead of silent fallbacks; breach semantics are unusually disciplined (explicit issues for `cash_unavailable`, `total_value_zero`, `unknown_sector_exposure`, never silent defaults).
- **Stable provider-independent identity**: `domain/market/ids.py` derives `sec:cik:`, `sec:equity:`, `sec:fact:` (content-keyed), `sec:doc:` (hash-keyed); `finra:symbol:` explicitly provisional. Ticker resolution (`domain/market/identity.py`) is point-in-time over `known_at` + half-open `[valid_from, valid_to)`; ambiguity is never source/order-wins.
- **Centralized PIT enforcement**: `storage/duckdb.py` `as_of_clause()` forces `known_at <= as_of` on every analytical query with explicit date-vs-timestamp granularity; all consumers (screens, `portfolio_research`, `risk.py`) pass `as_of`.
- **Storage discipline**: `storage/mappers.py` keeps domain free of file I/O; parquet datasets have unique keys + deterministic rerun dedup; `raw_archive` write-once with content hashes; screens materialize with input fingerprints, stage counters, exclusion accounting, `calc_version`.
- **Broker boundary**: `robinhood/adapters.py` maps provider models → domain at the edge; deny-layered read-only registry; raw broker account ids never persisted (one-way `local_account_id`); provider method names never surface as LLM tools.
- **Vendor encapsulation**: `edgar_client.py`, `finra_client.py`, `analyst_client.py` each state "tools.py never talks to X directly".
- **Agent loop quality**: capability-gated bounded tool surface; evidence-token budget with hard-stop; deterministic unavailable-data response on failed tools (no model invention); rendered-text evidence hashing with source/as_of/row-count metadata; full run/event/model-call recording; redaction at the observability boundary.
- **FINRA analysis layering**: raw rows never reach the main model; deterministic metrics + strictly validated small-model prose; explicit `page_complete`/`query_complete`/`analysis_complete` coverage flags.
- **Risk**: mandate validation lives in-domain, free of file I/O; `evaluate_latest_mandate` is deterministic over the latest immutable snapshot.
- Fixture-based tests exist for every live path (`test_edgar_metrics`, `test_obligations`, `test_valuation`, `test_earnings`, `test_analyst_client`, `test_finra_*`).

## Current domain objects

Code-level (frozen dataclasses): `market/entities.py` (`Entity`, `EntityRelationship` — defined, unused), `market/securities.py` (`Security`, `TickerAlias`, `SecurityResolution`), `market/quotes.py` (`Quote`, provider-agnostic with price_type last/mid), `market/identity.py` (pure PIT alias resolver), `portfolio/models.py` (`Position`, `BrokeragePositionInput`, `PortfolioSnapshot`) + `snapshot.py`/`valuation.py`, `risk/` (`Mandate`, `RiskLimit`, `RiskBreach`, `RiskEvaluation`, `EvaluationIssue`), plus operational objects in `runtime.py`/`agent.py` (`ResearchRequest/Plan`, `ExecutionBudget`, `ToolCall`, `AgentEvent`, `ResearchResult`; run-scoped evidence = rendered-tool-text hashes).

Persisted datasets (`storage/parquet.py`): `entities`, `entity_aliases`, `securities`, `documents` (SEC companyfacts only), `financial_facts`, `short_interest`, `short_sale_volume` (**registered, no writer**), `screen_runs`/`screen_entries`, `portfolio_snapshots`/`positions`/`accounts`, `sector_mappings` (**readers only, no producer**), `company_obligations` (de-facto first typed extraction: typed rows + `excerpt` evidence + `content_hash` + `parser_version`).

**Absent:** `CorporateEvent`, `Evidence`, `Claim`, `MarketObservation`/`MarketReaction`, `Filing` as a first-class object, and any `market_prices`/OHLCV history.

## Current source/adaptor boundaries

- **SEC — two parallel paths**: (a) normalized: `research_data.refresh_sec_*` → `normalization.py` → parquet (`entities`, `entity_aliases`, `securities`, `documents`, `financial_facts`) with `filed_at`, `known_at=filed_at`, `accession`, `parser_version`, raw archived; (b) live: `edgar_client.py` (edgartools `Company(ticker)`) feeding `get_fundamentals`, `get_xbrl_facts`, `get_financial_statements`, `get_filing_section`, `diff_risk_factors`, `get_latest_earnings_release`; `obligations.py`/`valuation.py` build on (b).
- **FINRA**: `finra_client.py` (generic catalog/metadata/discovery + `ingestion_post_query` for refresh) + `finra_analysis.py` (deterministic briefing) → `short_interest` parquet via `normalization.normalize_finra_short_interest`; screens and `query_finra` consume both sides.
- **Analyst**: `analyst_client.py` (Yahoo unofficial quoteSummary, Slickcharts S&P 500) — keyless, crumb-refreshed, TTL-cached, structured unavailable-data responses.
- **Broker/market**: `robinhood/*` MCP client → provider models → `adapters.py` → domain → `portfolio_sync` persists snapshots; live quote/option tools.
- **Cross-layer**: `services/portfolio_research.py`, `analytics/screens.py`, `services/risk.py` are store-backed; `tools.py` handler maps dispatch with `TOOL_CAPABILITIES` capability gating.

## Top architecture gaps

1. **Two divergent SEC truth paths with inconsistent recency semantics (real problem).** Same EDGAR company-fact data normalized into `financial_facts` (exact accession + filed_at, archived, PIT-queryable) while live SEC tools re-derive it from edgartools with no accession/filed date; `_dedup_latest` approximates "most recently filed" by largest `fiscal_year` (docstring: dataframe has no filing-date column) so restatement order can silently select the wrong filing version for TTM EPS; live `Company(ticker)` bypasses the repo's own PIT alias machinery; the two paths can answer the same question with different values minutes apart.
2. **No CorporateEvent/Evidence/Claim layer; extracted assertions are tool text, not claims (real problem).** Narrative extraction returns raw text or unvalidated nested-LLM summaries (`get_earnings_summary` — summary + source label, no evidence-span identity); `obligations.py` is closest to typed extraction but nothing distinguishes a claim from supporting evidence, so contradiction/supersession (Rule 5/6) is impossible; run-scoped evidence ids are operational telemetry, not domain Evidence.
3. **Agent tool surface is dataset/vendor-shaped; one concept has several tool answers (real problem).** 27 source-organized tools; store-backed vs live paths answer overlapping concepts differently; roadmap §6 semantic tools (`resolve_entity`, `get_metric_series(..., as_of)`, `find_events`, `get_evidence`) do not exist. Generic FINRA data-plane tools are defensible (Rule 9) and should stay; the gap is missing canonical as_of-gated reads over normalized data.
4. **Newest extraction/persistence paths deviate from house PIT conventions (real problem, small surface).** `company_obligations` sets `known_at` = extraction time (`_known_at()`), not filing publication (the repo's own convention, cf. `financial_facts`) — a latent look-ahead inversion for future historical screens; `get_obligations` (a RESEARCH tool) implicitly mutates the PIT store on every call via `_maybe_persist` (agent-invoked side effect without an explicit Action boundary); `valuation.py` composes live price + live consensus + persisted obligations into an "adjusted forward EPS" with a single `source` label, no ingredient-as-of lineage, and imports the private `obligations._DEFAULT_TRIGGERED_TYPES`.
5. **Registered-but-unproduced datasets and no price history (debt becoming a gap).** `short_sale_volume` (roadmap marks Reg SHO ingestion `[x]` but no normalizer/refresh writes it) and `sector_mappings` (read by `services/risk.py`, written only by tests) have no in-repo producer; no `market_prices`/OHLCV exists, so MarketReaction reasoning is impossible regardless of event modeling.

## Top 5 recommended migrations (ranked)

1. **Unify the SEC fact read path on the point-in-time store (store-first read-through; retire the live-XBRL fiscal-year recency heuristic).** Correctness **high** (silent wrong-restatement selection → wrong TTM EPS; contradictory tool-vs-store answers); upcoming **high** (roadmap Phase 1 acceptance — restatements never silently wrong-order, series show accession/unit — and Phase 7 lineage); agent reasoning **high** (facts without filed/accession cannot be cited or knowable-at-T checked); cost **medium** (read-through over `financial_facts` + alias resolution, live fallback when the store lacks the fact; fixture tests exist to port). Keep filing-*text* tools (`get_filing_section`, `diff_risk_factors`) live — text normalization is a separate slice.
2. **Introduce CorporateEvent/Evidence/Claim as typed, persisted objects with evidence spans — starting by promoting the obligations extraction into the first evidence-attached event family.** Correctness **medium-high** (claims today are unverifiable tool text; Rule 5 structurally unenforceable); upcoming **high** (Phases 5/7); agent reasoning **highest** (support/contradict/supersede, disconfirming-evidence pass); cost **high but sliceable** (three datasets + domain objects + re-pointing the existing `company_obligations` writer; no new engine).
3. **Add store-backed semantic point-in-time agent tools for concepts the agent already asks about (canonical metric series; single shares-outstanding/EPS reader; later `find_events`/`get_evidence`).** Correctness **medium** (ends same-concept-different-number outputs); upcoming **high** (roadmap §6, Phase 7); agent reasoning **high** (one canonical answer per concept in the existing `row_count`/`as_of`/`truncated` envelope); cost **medium** (thin queries over as_of-gated `financial_facts`; deprecate live duplicates gradually per Rule 10).
4. **Align obligations/valuation with house PIT + provenance conventions.** Correctness **medium** (latent look-ahead in future historical queries over `company_obligations`; composites not auditable); upcoming **medium-high** (backtests/historical as_of); agent reasoning **medium**; cost **low-medium**. `known_at` = filing publication with `retrieved_at` = extraction; archive raw note text + content hash behind excerpts; public API replacing `obligations._DEFAULT_TRIGGERED_TYPES`; ingredient as-ofs + `calc_version` for valuation composites; warehouse writes as an explicit named Action, not an implicit chat-tool side effect.
5. **Complete the FINRA normalized ingestion surface: Reg SHO short-sale-volume normalizer + refresh writer (threshold-list membership after).** Correctness **low-medium today** (no wrong numbers, but a registered dataset and a roadmap `[x]` claim data no code writes); upcoming **high** (Phase 6 short-pressure/divergence features); agent reasoning **medium** (Reg SHO only reachable via generic `query_finra`; no known_at-gated series); cost **medium** (reuse `ingestion_post_query`; mirror `normalize_finra_short_interest` + fixtures).

## Suggested first vertical slice

**The audit supports Security → CorporateEvent → Evidence → Claim as the first vertical; Security → MarketObservation/MarketReaction is explicitly NOT ready** — no price history exists (`market_prices` not even registered; only live quotes and per-sync snapshot prices), so `find_market_reaction` is impossible until Phase 3 OHLCV ingestion.

Smallest slice (no repo-wide anything): (1) `CorporateEvent`/`Evidence`/`Claim` objects + parquet datasets + mappers reusing `sec:doc:` hashing and existing storage; no graph/registry/DSL (Rule 11). (2) Promote the existing obligations extraction: write event rows with evidence spans linked to archived raw note text; `known_at` = filing publication, `retrieved_at` separate (fixes gap 4); this becomes the reference pattern for later Form-4/8-K extraction and makes obligations queries/backfills honest as-of dates. (3) Deterministic contradiction/supersession (claim status derived from evidence links by code) only when a second extraction family creates real contradictions — until then, store + links only. Highest leverage because it feeds Phases 5/7, needs no new vendor data, and reuses the strongest existing machinery (documents dataset, aliases, mappers, fixture tests, the obligations extractor).

## Things explicitly NOT worth changing yet

- **Sector-mapping producer**: shipped `data/mandate.json` configures only single_position_weight and minimum_cash; sector limits would surface honest `unknown_sector_exposure` issues. Add a producer only when sector limits become real configuration.
- **Generic FINRA data-plane tools** (`list/describe/query/get_finra_datapoints`): deliberately bounded, metadata-first, coverage-flagged; Rule 9 permits. Keep.
- **`analyst_client.py` (unofficial Yahoo/Slickcharts)**: structured, cached, honestly labeled live data; replace behind the same module when licensed Phase 3 data arrives.
- **Live quote/option/portfolio sync flows and the Robinhood deny-layer**: already boundary-clean; do not restyle.
- **`finra:symbol:` provisional entity ids**: write-time resolution would invent current mappings for historical rows; the read-time PIT alias join is the correct design.
- **`EntityRelationship` as a populated dataset**: relationships expressible via entity_id joins; add when a real traversal need appears.
- **Qdrant/embeddings/search, extraction frameworks, repositories, CQRS, event sourcing, graph infrastructure**: roadmap Phases 4/8; no current requirement (Rule 11).
- **`get_earnings_summary`'s nested model call**: keep until the event/evidence vertical provides a validated extraction replacement.
- **runs.sqlite operational telemetry vs domain store**: correctly separate; do not unify.
- **`_provider_payload`/`_rows`/`_first` unwrap helpers duplicated in `tools.py` and `robinhood/portfolio.py`**: consolidate opportunistically when touched, not standalone.

No repository-wide migration is recommended; highest-value work is gap 1 (converge on the existing PIT store) followed by the section-6 slice.
